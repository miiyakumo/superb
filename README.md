# Superb

Windows 11 x64 上的桌面客户端。它从剪贴板或屏幕采集内容，发给你配置的 Chat Completions 接口，在置顶浮窗里流式阅读回答，并可选写回剪贴板。

## 开始使用

在仓库根目录运行：

```powershell
dotnet run --project src/Superb.Desktop
```

生成自带运行时的 Windows x64 目录：

```powershell
dotnet publish src/Superb.Desktop -c Release -r win-x64 --self-contained true -o artifacts/win-x64
```

运行该目录中的 `Superb.exe`，并保留同目录依赖。

### 连接模型

1. 首次打开进入「模型」，展开「快速连接 DeepSeek」，填入密钥后点「测试并保存」。接口和模型名可以留空，默认直连。代理在折叠的「高级连接设置」里。
2. 程序向 DeepSeek 官方 `/models` 查询可用模型，优先 `deepseek-flash`，其次 `deepseek-chat`，否则用列表第一项，再用固定文本做一次最多 64 tokens 的探测。只有收到完整文本后才加密保存密钥。探测不读取剪贴板或截图，也不展示、保存探测回答。
3. 新的快速配置为 200000 生成 tokens、300 秒超时，思考模式沿用模型默认。快速连接只在 DeepSeek 返回的模型信息标明支持图像时打开图像。新建的通用连接默认 200000 tokens、1000000 响应字符、120 秒超时；要不要发送图像，只看该连接上的「支持图像输入」，保存时不查询模型列表。已经保存的后端不会被自动提高限额。DeepSeek 官方端点的本地校验上限是 393216 tokens，其他端点是 200000。失败或取消不覆盖旧配置。
4. 已有可用后端时，下次启动直接进入浮窗。

模型连接统一保存端点、密钥、模型和生成参数。场景保留名称、系统提示词和可选的模型连接；未指定时使用当前默认连接。文字与图片使用同一选择规则，包含图片而当前连接不支持图像时，会提示更换连接。需要另一组模型或生成参数时，新建模型配置并让场景选择它。

场景快捷键保留；普通场景切换提示词，AI Coding 协作进入独立的持续任务流程。输入和截图都来自当前工作区队列，准备好后手动发送。用户消息直接附加输入，不再配置 `{input}` 模板或场景截图来源。代理、本机 HTTP、图像能力、温度及其发送开关、token 参数名称和流式兼容选项集中在折叠的「高级连接设置」里。tokens、超时和思考模式仍可直接调整；输入字节数与响应字符数限额保留在内部，编辑连接时原样保留已有值。

旧设置升级到 schema 4 前，会在设置文件旁保存 `.upgrade-*.bak` 原文备份。旧场景的模型与生成参数覆盖迁成独立模型配置并绑定该场景；自定义用户模板中的任务说明移入系统提示词。原有连接、凭据引用、技术限额和场景快捷键保留，固定文字／图片路由不再参与选择。

官方接口说明：[首次调用](https://api-docs.deepseek.com/zh-cn/)、[模型列表](https://api-docs.deepseek.com/api/list-models/)。连接失败时的区分和代理写法见 [后端连接排查](docs/backend-connectivity.md)。

## 悬浮工作区

浮窗默认局部穿透：空白、边框和只读答案文字上的点击、拖动、滚轮交给下层应用；按钮、输入框、场景选择、滚动条、标题拖动区和缩放角仍可操作。阅读回答时可用滚动条或翻页快捷键。显示和更新不主动激活窗口；点击输入框进入编辑，原窗口会失焦，也可以先按 Ctrl+Alt+E。编辑模式下答案区恢复滚动和选字，其他空白仍穿透。Esc 或「完成编辑」回到阅读，焦点留在当前窗口。鼠标选择场景保持阅读模式。「全穿透」让按钮等区域也穿透；Ctrl+Alt+E 退出全穿透并进入编辑，再按一次或按 Esc 回到阅读。编辑、设置、暂停、退出没有注册成功时，不能进入全穿透。

「读剪贴板」「两点截图」「截当前屏」只入队，不会自己把剪贴板发出去。两点截图在同一显示器上点两个对角，顺序不限；右键、Esc 或 60 秒超时取消，已有队列保留。「截当前屏」取鼠标所在显示器，采集时隐藏 Superb。队列最多 10 项，其中最多 5 张图片。正文与 PNG 字节合计不超过 16 MiB。每张图片不超过 3200 万像素，全部图片加在一起也不超过这个数。超出时提示，不删除已有项。

编辑时 Ctrl+Enter 发送，或使用发送快捷键。发送后「输入与队列」收起，给回答留出空间；手动展开后，后续流式更新不会再把它折叠。普通问答和算法场景回答出来之后再收集输入，会开始下一题，并换掉旧队列；AI Coding 保留任务记忆，将新材料用于后续分析。

频繁整屏提问可以点击「发送」旁边的「截屏并发送」，或按默认独占单键 **F4**：截取鼠标所在显示器，使用触发时的场景和模型，**只发送本次截图，单独开始一题**，不带上已有队列或输入框文字。截图成功并通过校验后才替换旧队列、问题和回答；截图失败、输入超限或模型不支持图片时保留原内容。取消会阻止迟到截图发送；暂停仍按原规则清空敏感内容。生成期间不会插入新请求，请先停止；「重答」重发已冻结的输入，不重新截图。原有 Ctrl+Alt+D 仍只截图入队。F4 独立启用，不连带开启其他独占键；完整消费无修饰键的按下、长按重复和释放，长按只触发一次。Alt+F4 等带修饰键的组合不由此动作接管。旧版未自定义的 Ctrl+Alt+X 升级为 F4，禁用状态和其他自定义绑定保留；若与已有绑定冲突，保留旧绑定并停用新键。系统注册失败会标记未生效，不降级成会透传的普通按键。浏览器事件是否完全被拦截应以实际平台测试为准，不承诺对所有监听机制不可检测。

「停止生成」留下已生成的部分和当前队列，标成未完成，可以手动复制，不自动写回。「重答」沿用上次冻结的输入、场景和模型，并产生一次新的请求。「新任务」取消当前任务并清空输入和回答。暂停、锁屏和退出会清掉敏感显示。自动写回需要单独开启，而且只写完整回答；请求期间剪贴板变了就跳过。

DeepSeek 官方端点可以选择「沿用模型默认」「直接回答（关闭深度思考）」或「深度思考」。思考过程只显示活动状态，不展示、不保留推理正文。官方端点因 token 耗尽失败时，浮窗会提供一次「直接回答」重试：仅这一次关闭思考，并把生成预算提高到至少 16384，不改已保存的默认值。

「外观」可调宽度、高度、背景不透明度（25%–100%）和回答字号（11–36）。文字保持实色，字号只影响回答。右下角绿色三角用于缩放。「舒适阅读」放大并专注回答，「恢复默认」回到 600×740、18 号字和不透明背景。点击输入和调节外观都可能让原窗口失焦，界面上有直接提示；需要继续原应用时，再点回那个窗口。

## AI Coding 三方协作

选择「AI Coding 协作」，把题目、当前代码、测试反馈分别复制后点击「读剪贴板」，收集完点击「分析」。单份反馈可以用「读取并分析」。后端模型维护任务记忆、判断进展和深入诊断；平台 AI 在 Web IDE 执行指令；用户负责转发。Superb 不读取牛客文件树，也不连接或自动操作其 IDE。

生成后，浮窗展示下一步方向、发送前的 `@` 文件操作、平台提示词和需要带回的证据。「复制平台提示词」只复制可直接转发的指令正文。平台修改后，把新代码、回复或实际测试结果带回继续分析；不用手工维护分类、轮次或摘要。后端可以直接给出算法、核心代码或完整函数。

任务记忆保留原始观察、带来源的结论以及指令和反馈记录。采集时间不代表文件版本；复制不代表执行；平台声称完成不等于验证通过。两次有独立执行证据的同策略失败，或出现回退，会要求后端深入分析并审核后续指令。缺少关键代码时，指令会要求取得具体片段，不能凭空修改未知文件。

「分析设置（本次会话）」可选择 JSON 动作协议或原生工具协议，并设置一次分析的调用数和总时限；默认 JSON 动作、最多 12 次调用、300 秒。「任务记录」展示之前的指令和反馈状态。模型连接的单次超时和生成限额仍生效。协议需与后端兼容；不会自动切换供应商或偷偷降级成普通问答。结构化动作使用非流式响应，界面显示分析、检索、诊断、审核和累计调用次数，不展示动作 JSON 或推理正文。

分析期间可继续读取剪贴板，新材料留在待分析队列，不改变正在执行的输入。停止仅丢弃本次未提交结论；重试沿用失败或停止时冻结的材料、模型和预算。失败后也可调整设置再点「分析」，使用当前设置处理保留的材料。新任务清空当前 Coding 任务；暂停、锁屏和退出清空所有任务材料，恢复不会找回它们。记忆只存在本次应用会话的内存中，不保存代码或对话到磁盘。

在 Coding 场景中，「截屏并分析」将截图和待分析材料加入当前任务，不开始另一个任务。普通场景的 F4 截屏单独提问行为保持不变。自动复制只写入完整、经审核的指令，剪贴板在分析期间发生变化时跳过。

任务原始材料最多 32 MiB / 1000 份，结构化记忆最多 512 条结论 / 256 条指令；达到限制会明确失败，不能静默丢弃材料。模型能力仍决定诊断质量；程序校验来源、流程和执行证据结构，不能证明模型技术结论一定正确。

## 已知边界

当前版本的实际范围如下。

- 协议只有 Chat Completions。AI Coding 支持原生工具调用或 JSON 动作协议，工具仅操作本地任务记忆与证据；没有 Responses API、Anthropic 原生协议、OCR、文件系统执行工具或浏览器自动化。
- 采集用的是 GDI `BitBlt` 和窗口 `PrintWindow`，不是 Windows Graphics Capture。黑帧和变化的几何范围会被拒绝，也不会退回整桌面。部分 GPU 窗口可能采不到。`PrintWindow` 超过 5 秒后不再使用其结果，底层调用本身停不掉。
- `WDA_EXCLUDEFROMCAPTURE` 设置成功，只说明这个属性能被读回来。它不能证明每一种采集链路都看不到浮窗。外部改掉保护属性之后，到下一次检测之间仍有窗口。
- 程序不隐藏进程，不注入其他进程，也不保证对抗高权限观察者。
- 阅读器不解析 HTML / XAML，不加载远程资源，不跳转链接，不执行命令。

桌面交互里哪些操作会使原窗口失焦，见 [焦点交互排查](docs/focus-interactions.md)。
