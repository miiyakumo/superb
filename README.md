# Superb

Windows 11 x64 上的桌面客户端。它从剪贴板或屏幕采集内容，经本地预处理后发给你配置的 Chat Completions 接口，在置顶浮窗里流式阅读回答，并可选写回剪贴板。

## 开始使用

在仓库根目录运行：

```powershell
dotnet run --project src/Superb.Desktop
```

生成自带运行时的 Windows x64 目录：

```powershell
dotnet publish src/Superb.Desktop -c Release -r win-x64 --self-contained true -o artifacts/win-x64
```

运行该目录中的 `Superb.exe`，并保留同目录依赖。

### 连接模型

1. 首次打开进入「模型」，展开「快速连接 DeepSeek」，填入密钥后点「测试并保存」。接口和模型名可以留空，默认直连。代理在折叠的「高级连接设置」里。
2. 程序向 DeepSeek 官方 `/models` 查询可用模型，优先 `deepseek-flash`，其次 `deepseek-chat`，否则用列表第一项，再用固定文本做一次最多 64 tokens 的探测。只有收到完整文本后才加密保存密钥。探测不读取剪贴板或截图，也不展示、保存探测回答。
3. 新的快速配置为 200000 生成 tokens、300 秒超时，思考模式沿用模型默认。快速连接只在 DeepSeek 返回的模型信息标明支持图像时打开图像。新建的通用连接默认 200000 tokens、1000000 响应字符、120 秒超时；要不要发送图像，只看该连接上的「支持图像输入」，保存时不查询模型列表。已经保存的后端不会被自动提高限额。DeepSeek 官方端点的本地校验上限是 393216 tokens，其他端点是 200000。失败或取消不覆盖旧配置。
4. 已有可用后端时，下次启动直接进入浮窗。

官方接口说明：[首次调用](https://api-docs.deepseek.com/zh-cn/)、[模型列表](https://api-docs.deepseek.com/api/list-models/)。连接失败时的区分和代理写法见 [后端连接排查](docs/backend-connectivity.md)。

## 悬浮工作区

浮窗默认是阅读模式：显示和更新不主动激活窗口。点击输入框进入编辑，原窗口会失焦；也可以先按 Ctrl+Alt+E。Esc 或「完成编辑」回到阅读，焦点留在当前窗口。鼠标选择场景保持阅读模式。「穿透」把鼠标交给下层应用。Ctrl+Alt+E 在阅读和编辑之间切换；若当前是穿透，第一次按下会退出穿透并进入编辑，再按一次或按 Esc 才回到阅读。编辑、设置、暂停、退出没有注册成功时，不能进入穿透。

「读剪贴板」「两点截图」「截当前屏」只入队，不会自己把剪贴板发出去。两点截图在同一显示器上点两个对角，顺序不限；右键、Esc 或 60 秒超时取消，已有队列保留。「截当前屏」取鼠标所在显示器，采集时隐藏 Superb。队列最多 10 项，其中最多 5 张图片。正文与 PNG 字节合计不超过 16 MiB。每张图片不超过 3200 万像素，全部图片加在一起也不超过这个数。超出时提示，不删除已有项。

编辑时 Ctrl+Enter 发送，或使用发送快捷键。发送后「输入与队列」收起，给回答留出空间；手动展开后，后续流式更新不会再把它折叠。回答出来之后再收集输入，会开始下一题，并换掉旧队列。

「停止生成」留下已生成的部分和当前队列，标成未完成，可以手动复制，不自动写回。「重答」沿用上次冻结的输入、场景和模型，并产生一次新的请求。「新任务」取消当前任务并清空输入和回答。暂停、锁屏和退出会清掉敏感显示。自动写回需要单独开启，而且只写完整回答；请求期间剪贴板变了就跳过。

DeepSeek 官方端点可以选择「沿用模型默认」「直接回答（关闭深度思考）」或「深度思考」。思考过程只显示活动状态，不展示、不保留推理正文。官方端点因 token 耗尽失败时，浮窗会提供一次「直接回答」重试：仅这一次关闭思考，并把生成预算提高到至少 16384，不改已保存的默认值。

「外观」可调宽度、高度、背景不透明度（25%–100%）和回答字号（11–36）。文字保持实色，字号只影响回答。右下角绿色三角用于缩放。「舒适阅读」放大并专注回答，「恢复默认」回到 600×740、18 号字和不透明背景。点击输入和调节外观都可能让原窗口失焦，界面上有直接提示；需要继续原应用时，再点回那个窗口。

## 已知边界

当前版本的实际范围如下。

- 协议只有 Chat Completions。没有工具调用、Responses API、Anthropic 原生协议、OCR 或浏览器自动化。
- 采集用的是 GDI `BitBlt` 和窗口 `PrintWindow`，不是 Windows Graphics Capture。黑帧和变化的几何范围会被拒绝，也不会退回整桌面。部分 GPU 窗口可能采不到。`PrintWindow` 超过 5 秒后不再使用其结果，底层调用本身停不掉。
- `WDA_EXCLUDEFROMCAPTURE` 设置成功，只说明这个属性能被读回来。它不能证明每一种采集链路都看不到浮窗。外部改掉保护属性之后，到下一次检测之间仍有窗口。
- 程序不隐藏进程，不注入其他进程，也不保证对抗高权限观察者。
- 阅读器不解析 HTML / XAML，不加载远程资源，不跳转链接，不执行命令。

桌面交互里哪些操作会使原窗口失焦，见 [焦点交互排查](docs/focus-interactions.md)。
