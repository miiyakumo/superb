# Superb

面向 Windows 11 x64 的受控 Agent 转发客户端。使用原生 WPF 阅读面板、Win32 采集与剪贴板接口，以及可配置的 Chat Completions 后端。

**当前为 0.2.0 开发版本，尚未完成 Windows 桌面采集保护验收，不能作为已验证的保密产品发布。** 已实现采集 → 本地处理 → 受控发送 → 流式阅读 → 可选剪贴板输出的代码闭环。采集排除、焦点行为、多屏 DPI、锁屏和系统剪贴板兼容性需要实测；没有任何采集软件组合被标记为已通过。

## 运行与构建

开发环境需要 .NET 10 SDK。Windows 用户可以运行：

```powershell
dotnet run --project src/Superb.Desktop
```

生成自带运行时的 Windows x64 文件夹：

```powershell
dotnet publish src/Superb.Desktop -c Release -r win-x64 --self-contained true -o artifacts/win-x64
```

运行生成目录中的 `Superb.exe`，保留同目录依赖。无需管理员权限。首发开发基线为 Windows 11 x64（构建 22000+）；这只是启动约束，正式支持范围以验收矩阵为准。没有配置供应商、API 密钥或有效后端时不会发送网络请求。仅允许一个本机会话实例。

## 首次使用

1. 首次打开进入“连接模型”。填入 DeepSeek 密钥，点击“测试并保存”；无需填写接口和模型。默认直连，代理放在折叠的“高级连接设置”中，按需选择。
2. 应用从 DeepSeek 官方 `/models` 获取可用模型，优先选择 `deepseek-flash`，其次 `deepseek-chat`，否则选择列表首个模型；用固定文本做一次最多 64 tokens 的测试。只有完整文本响应通过后，才加密保存密钥并返回“提问”。失败或取消不覆盖旧配置、不自动重试或更换线路。图像能力仅在服务端模型元数据明确声明时启用。
3. 在“提问”输入问题并发送，或点击“问剪贴板”；回答直接显示在同一页。每次提问独立，不自动附带历史。需要浮窗时点击“悬浮阅读”；主窗口收起后，全局快捷键仍可显示阅读面板。
4. “截图提问”首次会引导到“高级设置 → 截图范围”。选择窗口、显示器或矩形后应用目标，再提问。窗口目标重启后需重选，移动或改变尺寸后需重新确认；模型须支持图像。
5. 其他服务商、已有后端、完整端点、生成参数、处理规则、固定路由、自动同步、快捷键均位于“高级设置”的折叠分组。连接成功后获取到的模型列表也可在“模型与连接”的模型框选择；编辑后需保存。既有固定路由保持不变，并在提问页显示实际接收方。
6. 完整回答可手动复制。自动写回需独立启用；剪贴板在请求期间变化时跳过自动写回。暂停、锁屏和退出清除输入、回答和密钥输入框；恢复按钮只在未就绪时显示。

DeepSeek 官方接口依据：[首次调用](https://api-docs.deepseek.com/zh-cn/)、[模型列表](https://api-docs.deepseek.com/api/list-models/)。快速配置只向 `api.deepseek.com` 发出模型查询和固定文本测试，不读取剪贴板或截图，不显示或保存测试回答。已有 DeepSeek 可直接使用；重新快速配置需填入密钥。需要保留自定义生成参数时使用高级编辑器。

Live Clipboard 需在每次会话中明确授权输入格式、接收后端、期限及是否允许自动发送。期限默认 10 分钟，上限 60 分钟。400 ms 去抖、至少 2 秒采集间隔、内容哈希去重、过滤本应用输出；繁忙时合并为最新一次剪贴板变更。启动授权时不自动读取已有剪贴板。停止 Live Clipboard 会撤销后续自动输入并丢弃尚未发送的自动准备任务，但不会把已经提交的请求伪装成“可撤回”；现有请求可独立取消，紧急暂停仍会遮蔽敏感显示并停止本地输出。

默认全局快捷键：

| 快捷键 | 动作 |
| --- | --- |
| Ctrl+Alt+1 / 2 | 问剪贴板 / 问预设区域 |
| Ctrl+Alt+3 / 4 | 显示或收起阅读面板 / 复制完整回答 |
| Ctrl+Alt+5 / 6 | 取消当前任务 / 紧急暂停 |
| Ctrl+Alt+7 | 发送已准备输入 |
| Ctrl+Alt+8 / 9 | 阅读面板向下 / 向上翻页 |
| Ctrl+Alt+0 / Q | 打开控制中心 / 退出 |

快捷键冲突会列出注册失败的动作。阅读面板不激活、不进入任务栏；设置窗口只在启动和用户明确打开时激活。可以拖动阅读面板标题栏、从右下角调整大小；位置、大小、字号和显隐状态会保存。

## 预处理与固定路由

处理规则按数组顺序执行，裁剪、遮盖的坐标相对上一步图像。以下示例仅用于图像：

```json
[
  { "Kind": "Crop", "Required": true, "Rectangle": { "X": 0, "Y": 0, "Width": 800, "Height": 600 } },
  { "Kind": "Mask", "Required": true, "Rectangle": { "X": 20, "Y": 20, "Width": 180, "Height": 40 } },
  { "Kind": "Resize", "Required": true, "MaxDimension": 1600 },
  { "Kind": "Template", "Required": true, "Template": "请解释图片内容。{input}" }
]
```

文本可使用 `NormalizeText` 和 `Template`。不处理正文时使用空数组 `[]`。仅 `Required: false` 且 `SkipOnFailure: true` 允许失败后跳过；界面显示跳过计数。强制步骤失败不发送。新图像逐像素重新编码，遮盖区域为实色像素，不附加原图或元数据。

固定路由只依据处理产物是否带图像，使用配置中列出的后端 ID：

```json
{ "TextBackendId": null, "ImageBackendId": null }
```

`null` 使用手动选择。自动同步固定绑定获授权的一个后端；路由指向另一个后端时拒绝发送。用户文本、截图内文字和模型回答不会成为策略指令。

## 存储和边界

- 配置保存在 `%LOCALAPPDATA%\Superb\settings.json`，凭据单独保存在 `credentials\*.dpapi`，采用当前用户 DPAPI。配置导出去掉凭据引用及采集目标。规则模板属于持久配置，不要把敏感正文写进模板。
- 截图、剪贴板正文、回答和请求历史默认只在内存；无应用内容日志、自动遥测、崩溃上传或临时图像文件。暂停/锁屏/退出清除显示和会话引用，默认只清除仍由本应用拥有的剪贴板输出。托管字符串、图形缓冲、系统分页与第三方转储无法保证绝对擦除。
- 所有后端流量经过同一个客户端，验证 HTTPS 证书，禁用重定向、Cookie 和自动重试。每个后端可选择直连、系统代理或自定义 HTTP/HTTPS/SOCKS5 代理；旧配置仍为直连。普通网络代理填写在“自定义代理地址”，不要替换模型端点。模型协议目前仅实现 Chat Completions；不支持工具调用、Responses、Anthropic 原生协议、OCR 或浏览器自动化。
- 每次请求独立，流必须包含合法 `finish_reason: stop` 及 `[DONE]` 才完成。截断、长度上限、限流及内容过滤结果不会自动写回。手动重试沿用冻结后的输入和后端，但创建新的尝试 ID，可能产生新的计费。
- 阅读器只生成本地文本与代码段，不解析 HTML/XAML、不自动加载链接或执行命令。系统剪贴板历史/云标记不阻止其他进程读取当前剪贴板。
- 当前采集原型采用 GDI `BitBlt` 和窗口 `PrintWindow`，不是 WGC。拒绝黑帧和变化的几何范围，不做全桌面回退。部分 GPU 窗口可能无法正确采集；需要用验收证据冻结支持范围。PrintWindow 超过 5 秒后停止消费结果，底层调用不能强制终止，最多保留一个在途采集线程。
- `WDA_EXCLUDEFROMCAPTURE` 设置成功只表示属性可检查，不能证明所有采集链路安全。运行中每 100 ms 及敏感渲染前检查；外部改变保护与检测之间存在时间窗口，必须逐帧验证。不存在进程隐藏、注入、关闭系统安全提示或对高权限攻击者的保证。

## 验证

连接问题先在“高级设置 → 模型与连接”保存正确的连接方式，再点“测试已保存后端”。该动作使用同一请求实现和固定文本 `Reply with OK.`，不读取剪贴板、不显示或写回测试回答。界面会区分 DNS、TCP、TLS、代理、HTTP 状态和响应格式错误；模型不支持 `temperature` 或 `max_tokens` 时，可关闭前者并选择 `max_completion_tokens`。详细步骤见 [后端连接排查](docs/backend-connectivity.md)。

跨平台核心测试（自包含控制台测试器，失败时非零退出）：

```powershell
dotnet build Superb.slnx -c Release
dotnet run --project tests/Superb.Tests -c Release
```

Windows 专用测试：

```powershell
dotnet run --project tests/Superb.WindowsTests -c Release
dotnet run --project tests/Superb.WindowsTests -c Release -- --interactive
# 仅在可覆盖当前剪贴板的测试会话运行：
dotnet run --project tests/Superb.WindowsTests -c Release -- --clipboard
```

普通 Windows 测试处理合成位图、一次性合成凭据、本机模拟后端、配置保存失败回滚及 WPF 页面离屏渲染。可追加 `--render-dir artifacts/ui` 导出三个页面的 PNG；这不等于交互式桌面操作验证。`--interactive` 检查窗口属性，不能替代采集排除实测；`--clipboard` 会覆盖当前剪贴板。CI 固定使用 Windows Server 2025，运行核心/真实代理传输/图像/DPAPI 到 HTTP 集成测试并打包，同时保留操作系统、SDK 和测试记录。其结论不等于 Windows 11 桌面行为已验收。

详细设计、需求覆盖和发布门槛见 [架构与需求映射](docs/architecture.md)、[Windows 验收矩阵](docs/acceptance.md)、[本次验证记录](docs/verification.md)。原始需求保存在 [requirements.zh-CN.txt](docs/requirements.zh-CN.txt)。

## 网页焦点与按键事件诊断

本地测试页位于 `tools/event-probe/index.html`，记录窗口失焦、页面隐藏、控件焦点及按键事件，支持手动导出 JSON / HTML。运行 `python -m http.server 8765 --bind 127.0.0.1 --directory tools/event-probe` 后访问 `http://127.0.0.1:8765/`。

Windows 自动实验使用真实阅读窗口与热键管理器的隔离测试宿主，在有界面的 Edge / Chrome 中采样，鼠标与键盘由 `SendInput` 合成。每轮同时确认原生动作、浏览器前台状态和网页事件；没有动作证据时不能把零事件当作通过。它不加载用户配置或调用模型，不屏蔽事件，也不代表其他网页或本机监控不可检测。完整步骤和报告边界见 [测试说明](tools/event-probe/README.txt)。独立工作流为 `.github/workflows/focus-probe.yml`。

### 场景预设与可编辑快捷键

主界面提供 AI Coding 协作、算法题、通用问答三个入口，默认输入为剪贴板，默认发起键分别为 Ctrl+Alt+C、Ctrl+Alt+A、Ctrl+Alt+G。按钮注明输入来源，与快捷键调用同一场景。每次只发送当前场景的 system 提示词和本次 user 消息，不携带历史或其他场景内容。

在“高级设置 → 场景管理”编辑名称、输入来源（剪贴板 / 提问输入框 / 预设截图范围）、系统提示词、含 `{input}` 的用户模板，以及独立后端、模型、温度与 token 覆盖。后端留空时遵循当前选择及固定路由；明确指定场景后端时优先使用它，失败不切换。场景模板在全局预处理之后应用，遮罩等必要步骤不会被绕过。后端禁用 temperature 时场景温度覆盖也不会使它重新发送。场景运行会停止正在进行的 Live Clipboard 授权，避免后台自动请求抢占本次手动请求。当前输入、回答及历史不写入场景配置；提示词与模板本身会保存。

“偏好与快捷键”统一列出所有动作和场景的绑定，可逐项修改、启停、恢复默认：

- 普通组合键：例如 Ctrl+Alt+C。修饰键可能到达网页，不承诺零网页事件。
- 独占单键：F1–F11、F13–F24。必须开启“独占单键接管”才生效；其按下、重复与释放由 Superb 消费，其他应用失去该单键功能。模式切换会填入建议值，仍可编辑；建议值不代表无冲突。例如 F6 常用于切换焦点，F11 常用于全屏，F13–F24 可能需要专用硬件。F12、Windows 键组合及若干保留组合不允许配置。

接管总开关默认关闭，默认绑定为普通组合键。新建自定义场景的快捷键默认禁用。重复绑定在保存前拒绝；其他程序已注册的冲突会显示失败动作，网页自定义快捷键无法全面预判。请松开所有按键后保存或退出。完整主窗口收起前仍检查设置、暂停和退出入口可用。

配置升级到 schema 2：保留旧自定义组合键；旧“独占阅读键”开关开启时迁移为 F6/F7/F8 独占绑定并保留接管开启状态。新配置不再使用固定阅读键覆盖。旧配置只在显式保存时写回。

原生测试现覆盖两浏览器、两模式：普通模式 17 场景 × 3 次，独占模式 30 场景 × 3 次，共 282 次。场景触发使用本机合成 HTTP 接口核对 system/user 消息、模型及请求次数；测试不访问真实模型或读取用户配置。运行方式见 `tools/event-probe/README.txt`。
