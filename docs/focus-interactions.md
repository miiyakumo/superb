# 焦点交互排查

## 2026-10-24：只读浮窗

当前浮窗已删除编辑／完成编辑按钮、手输输入框和编辑模式。问题、补充要求统一从剪贴板或截图进入材料队列；回答通过复制按钮取用，滚动条和翻页快捷键仍可操作。

右下角缩放手柄固定为普通箭头，保留拖动缩放；浮窗的鼠标激活请求和键盘焦点请求始终被拒绝。全穿透用默认 Ctrl+Alt+E 切换恢复；原编辑动作的自定义按键、模式和启用状态迁到这个恢复入口，没有可靠恢复键时拒绝开启全穿透。程序设置仍接受明确点击和文字输入。

本轮通过窗口激活消息、只读控件、原生命中区域、拖拽事件、请求与队列集成检查；未重跑实际鼠标输入或浏览器事件矩阵。以下保留旧交互设计和当时的测试记录，其中编辑模式、输入框和浮窗外观入口已退出当前界面。

## 2026-10-23 历史记录

目标是保留用户当前选择的前台窗口，移除不必要的激活。正常文字输入与系统窗口操作仍需要焦点；界面会在操作前提示，不再把“不主动调用激活”表述为“任何交互都不会失焦”。

## 输入与外观的可见提示

输入框上方直接显示“点击输入会使原窗口失焦；完成后请点击原窗口继续”。外观面板内直接显示“调整外观可能使原窗口失焦；完成后请点击原窗口继续”，外观按钮、滑块、预设和缩放手柄的悬停说明也使用相同的谨慎表述，移除“保持原窗口焦点”的承诺。阅读模式状态行同步明确点击输入会失焦。

这些说明随对应区域显示，不弹出确认框，不改变焦点处理逻辑。外观提示回应用户观察到的情况，不表示本轮已复现新的焦点问题；历史原生测试证据保持以下记录。此次构建 0 警告、0 错误，普通 Windows 回归 52/52，离屏渲染位于 `artifacts/ui-focus-notices`，已检查外观面板的提示布局；未重新执行原生鼠标或浏览器矩阵。

| 操作 | 本轮处理 | 提示／建议 |
| --- | --- | --- |
| 浮窗普通按钮、滚动条、展开折叠、翻页和复制 | 编辑模式也拦截非输入区域的鼠标激活；拒绝普通控件取得键盘焦点 | 不需要先进入编辑 |
| 场景下拉选择 | 移除自动进入编辑；选择框和选项不取得键盘焦点 | 浮窗用鼠标选择；键盘配置场景在设置页完成 |
| 外观滑块和右下角缩放 | 移除进入编辑的鼠标预览事件，控件不取得键盘焦点；关闭系统边框缩放，统一使用自有缩放手柄 | 保持原窗口焦点，无需进入编辑 |
| 输入过程中打开／关闭外观 | 保留已聚焦输入区的展开状态；小窗口优先保留输入空间，外观区滚动显示；仅滚动光标到可见位置 | 输入焦点、选区和光标不变，可以直接继续输入 |
| 暂停／恢复 | 浮窗保持被动点击；设置页的两个紧急动作也拒绝鼠标激活且不可聚焦 | 暂停仍取消任务、停止同步并清空输入与回答；恢复不找回内容、不续接请求 |
| 标题拖动 | 改为 WPF 鼠标捕获移动位置，移除系统 DragMove | 标题悬停提示 |
| 悬停激活 | 浮窗编辑模式和设置窗口同样拒绝 WM_MOUSEACTIVATE 中的悬停请求，避免显示在鼠标下面就激活 | 浮窗只有输入区域的明确左键操作允许鼠标激活；设置接受明确的鼠标点击 |
| 编辑／阅读模式、发送和流式更新 | 不主动激活、清除键盘焦点或恢复历史前台 | Esc／完成编辑只改变模式，不自动回到旧应用 |
| 输入问题、输入法、编辑模式下选择回答文字 | 需要 Superb 的键盘／文本交互焦点 | 模式提示、输入框和回答区提示“会使原窗口失焦”；整段复制可用复制按钮或快捷键 |
| 显示设置与连接成功 | 显示不激活；连接完成时若设置或其系统对话框在前台，保留设置，不自动隐藏 | 点击设置进行配置会使原窗口失焦；主动返回浮窗时才收起设置 |
| 截图 | 保留采集前临时隐藏窗口，以免把自身覆盖层采入；两点选点仍消费完整点击周期 | 截图按钮提示：若 Superb 当前有焦点，隐藏会使 Windows 转移焦点；建议目标应用在前台时使用截图快捷键 |
| 收起浮窗／设置、返回浮窗、退出 | 隐藏或关闭活动窗口必然由 Windows 重新选择前台 | 对应按钮提示，不强制指定接收焦点的窗口 |
| 穿透模式 | 只改变鼠标命中，不主动移交键盘焦点 | 按钮和模式文字提示：点击目标应用后继续输入 |
| 导出配置 | 系统保存对话框需要焦点 | 导出按钮提前提示 |
| 普通组合快捷键 | 保留系统注册逻辑，不干预原应用全部输入行为 | 设置页提示：修饰键可能触发原应用自身操作或改变焦点，需避开冲突绑定 |

## 原生实测与修复结果

- 核心测试 **61/61**；完整 Windows 测试（含原生鼠标）**49/49**。
- Chrome **155.0.8059.85**、Edge **155.0.4283.62**，各 **10 个场景 × 3 轮**，共 **60 轮**，原生动作全部确认。需要保留焦点的 **48 轮**均没有网页 `window.blur`、隐藏、丢弃记录或前台窗口改变；其余 **12 轮**是普通窗口激活／切换标签的正对照，正常记录了失焦或隐藏。
- 原生 WPF 检查同时统计外部窗口 `Deactivated`、输入控件 `LostKeyboardFocus`、浮窗 `Activated` 和最终前台句柄，避免漏掉短暂失焦再恢复。文字选择、首次点击并输入、系统保存对话框及主动隐藏活动浮窗作为必要焦点变化的正对照，均验证了实际效果。

实测发现并修复：

1. 回答区开启选字却始终不可聚焦，导致真实拖选失败。现仅在编辑模式允许阅读控件取得焦点，实际非空选区已验证，阅读模式继续不可聚焦。
2. 编辑模式右键回答区虽然没有菜单，WPF 仍会将焦点切入。现处理非活动浮窗回答区的无功能右键按下事件，验证没有前台或键盘焦点变化。
3. 输入框的滚动条鼠标预览事件误触发进入编辑。现排除滚动条、滑块和按钮后代，验证草稿确实滚动且保留阅读模式与原窗口焦点。

覆盖四个外观滑块、缩放手柄、标题移动、舒适／默认预设、两种模式的场景下拉、正文滚动条／滚轮／回到最新、右键、发送／读取／复制／重答／暂停按钮的鼠标命令链、输入框滚动与输入、设置显示与输入、导出对话框取消、截图右键／Esc 取消、两点选点完整点击消费、穿透和收起。按钮命令链在隔离阅读器中核对，不读写用户剪贴板或调用模型；设置／截图取消等使用隔离的生产 MainWindow。选点成功只核对坐标，不采集或保存桌面像素。

测试宿主还修复了两个校准问题：滚动用例明确从顶部开始，避免生产的自动跟随导致“本来就在底部却要求向下滚动”；Edge 仅在采样前关闭属于新测试浏览器的启动弹窗，并重新确认实际前台句柄，未通过校准的轮次不算通过。浏览器增加 `--mouse-only` 模式，不因正在运行的用户实例占用全局键而跳过鼠标实测；该模式仍验证显示保护和所有原生动作。

## 补充：正在输入时打开外观

此前的外观测试覆盖外部应用保持焦点，遗漏了草稿框已经取得焦点时的路径。打开外观无条件折叠输入区会使 WPF 移走输入焦点；小窗口原先为回答预留的空间也可能把输入区压到零高度。现在打开外观时保留正在输入的区域；编辑时优先保留输入空间，并按可用高度压缩可滚动的外观区。布局稳定后仅将原光标滚入可见范围，不调用聚焦／激活方法，也不修改选区。

新增原生鼠标用例在 **600×740、360×540、360×480** 三种尺寸中，逐一点击外观打开、在长草稿原选区继续输入合成字符、点击关闭。核对文本／选区／光标、实际可见输入高度及光标位置、键盘焦点、原生前台 HWND、`LostKeyboardFocus` 和 `Deactivated` 计数，全程没有焦点丢失。该用例可用 `--appearance-edit-only` 单独运行。

本次完整 Windows 回归 **54/54**，核心 **61/61**；构建和自带运行时发布均成功，0 警告、0 错误。记录：`artifacts/appearance-focus-validation/`；新版：`artifacts/appearance-focus-fix-win-x64/Superb.exe`。本次未重跑先前的双浏览器 60 轮矩阵，不将历史浏览器数据作为新增用例的证据。

## 补充：暂停／恢复入口

原生实测未复现浮窗暂停／恢复导致失焦：外部输入框、草稿编辑器、回答选字控件三种初始焦点均保持不变。设置页此前接受所有明确点击激活，且暂停／恢复按钮可聚焦，存在不必要的焦点转移路径。现对这两个动作拒绝鼠标激活并禁用按钮聚焦，普通设置输入仍允许明确点击激活。为暂停及恢复补充内容清空与焦点行为提示。输入因暂停变为只读、草稿与回答被清空的既有语义不变。

新增隔离生产 MainWindow 原生测试，真实点击暂停和恢复，覆盖以上三种浮窗状态及设置页外部输入场景；检查命令确实执行、内容清空、暂停只读、恢复不重现内容，以及键盘焦点、前台 HWND、`LostKeyboardFocus`、`Deactivated`。四条路径均通过。恢复测试只在隔离宿主中模拟会话监听注册成功，不读取用户配置、不访问真实模型、不修改剪贴板。此前被并发鼠标输入打断的轮次不计为通过；用户确认桌面空闲后的轮次通过。
