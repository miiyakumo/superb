# Superb 网页交互痕迹对抗测试

日期：2026-10-21。

2026-10-22 增量：本轮已完成窗口枚举、弹窗内容保护修复、三轮原生控件/GDI 对照和网页文件导入实测；详细证据与剩余边界见 [2026-10-22 对抗诊断报告](adversarial-report-20261022.md)。以下保留上轮历史记录，不把旧轮次状态改成新结论。

## 工具与范围

新版实验台位于 `tools/interaction-probe/`，旧版 `tools/event-probe/` 保留。新版默认不记录，点击开始后只在当前页面内存收集事件；导出 JSON 是显式操作。记录 key/code 可能还原输入，请只在靶场输入合成文本。剪贴板、拖放、输入和选区记录元信息，不保存正文或文件内容。

启动：

```powershell
node tools/interaction-probe/serve.mjs
```

浏览器打开 `http://127.0.0.1:8787/`。服务只绑定本机，提供静态白名单文件，不接收浏览器日志。端口可用命令行第二个参数指定。

本工具观察的是浏览器事件，无法枚举其他进程、检测桌面截图、直接识别受保护浮窗或全局输入钩子。失焦、孤立 keyup 和未观察到事件都不能单独归因于 Superb。`isTrusted=true` 也不能证明事件来自物理键盘；操作系统输入注入可能得到同样的标记。

## 精选场景

| 场景 | 对抗操作 | 需要保留的证据 |
| --- | --- | --- |
| A 基线与正对照 | 无 Superb 时输入 a、长按、点击靶标、滚动；切到另一标签和普通窗口 | 可信按键周期、点击计数、blur 与 hidden 的独立正对照；未通过则后续零事件无效 |
| B 普通组合键 | 网页保持焦点，显隐、翻页浮窗，随后输入 a | 先确认动作发生和绑定注册，再看修饰键残留、孤立 keyup、后续误输入；按实际绑定测试 |
| C 独占与修饰对照 | 独占单键、长按、完整释放，再测试带修饰的同键 | 核对动作发生、去重、按下与释放是否成对、修饰组合是否仍被页面接收 |
| D 阅读与主动编辑 | 只显示、更新、翻页浮窗，再分别编辑和打开设置 | 同时保留页面焦点、控件焦点、可见性和原生动作，不能把 focusout 当作 window.blur |
| E 两点选区与取消 | 在页面可点击区域选两个角；右键、Esc 分别取消；随后普通点击 | 选点前后底层点击计数、取消后恢复，以及截图是否实际进入队列；网页不能代替截图结果验证 |
| F 穿透命中 | 浮窗覆盖靶标，比较普通模式与穿透模式下点击和滚轮 | 原生模式与位置、网页点击与滚动计数；浮窗外的点击作对照 |
| G 剪贴板边界 | 主动 copy/cut/paste，再让 Superb 读取剪贴板 | 前者的类型与长度元信息；不得把后者无事件判作“未读取” |
| H 全屏与设置 | F11 全屏后开设置；另测网页 Fullscreen API | 浏览器全屏和 Fullscreen API 分开记录，blur 不等价于退出全屏 |
| I 记录器边界 | 暂停、继续、清空、超过容量、合成事件与导出 | 环形覆盖数、保留条数、可信标记、隐私字段和原始时间线；合成事件不是原生测量 |

每项先记录基线，再标记操作，核对 Superb 的实际状态后暂停和导出，建议重复三次。零事件但动作未发生、热键未注册或正对照失败时，应标记为无效测量。捕获和冒泡是同一事件的不同观测阶段，不能按两次物理输入解释。

## 隔离宿主

`tests/Superb.WindowsTests/FocusHost.cs` 继续复用生产 `ReaderWindow`、`Protection` 和 `HotkeyManager`；本次补入编辑入口、穿透入口和两点选区命令。通过 `--focus-host` 启动，标准输入接受逐行 JSON 命令，包括 `show`、`render`、`read`、`edit`、`through`、`exclusiveOn`、`exclusiveOff`、`selectCorners`、`state` 和 `quit`，每条带 `id`。

宿主不加载用户配置、不读取剪贴板或桌面像素、不使用真实模型凭据。选区命令仅验证生产选点钩子和点击生命周期，不执行截图采集或发送。状态返回选区阶段、完成/取消计数、保护属性、前台窗口与注册失败；有注册冲突的动作不能用于宣称有效的对抗测量。设置入口仍使用普通 WPF 正对照窗口，不代表完整设置窗口的流程验证。

## 应用内浏览器补充验证

应用内浏览器可以作为记录页面，已通过工具实际打开和操作，而不只做纯逻辑自测：输入 `a` 得到捕获／冒泡的 keydown 与 keyup，一个完整周期、零未配对释放；点击靶标累计 1 次。暂停后输入 `b`，原始事件数保持 896、保留日志保持 865，暂停门控有效。

另启动隔离原生宿主，确认 `Ctrl+Alt+3` 的 toggle 注册成功、保护有效、初始隐藏。在应用内页面通过浏览器工具发送该组合键后，网页收到 Control、Alt、Digit3 的完整可信事件周期；原生宿主仍隐藏，动作列表仍为空。本次工具输入没有触发已注册的原生显隐动作。因此可以用它验证网页记录器，但不能把这条输入链路的事件结果用于验收 Windows 全局快捷键／钩子。

这个结果不表示应用内浏览器不能作为原生测试的页面，也不代表用户手动按键无效；它只限定当前浏览器工具自动输入方式的实测范围。原生 A–I 验收仍未完成。宿主已退出并释放临时快捷键。

证据保存在本地 `artifacts/interaction-iab/`：`summary.json` 为输入／点击／暂停摘要，`browser-chord.json` 与 `native-chord.json` 为同一组合键的网页／宿主观测，`result.png` 为实际页面截图。网页 `isTrusted=true` 不能用于推断事件已经过 Windows 的原生钩子。
