## 2026-10-24：两个工具的连续 AI Coding 会话

`CodingSession` 持有不可变原始观察、带 EvidenceRef 的事实、指令和执行反馈。采集时间不保证代码新旧，复制不代表执行，平台自述不能代替测试证据。模型只获得 `retrieve_material` 和 `submit_result` 两个原生函数；只有一个持续工作的技术负责人，不再有专家／审核角色、旧动作协议、旧工具别名或调度分支。

`CodingAgentRunner` 自动提供完整已提交记忆、原始材料目录及有界新近片段。材料够用可以一次提交；检索由 `CodingMaterialStore` 按关键词、分页或批量字符范围取回冻结原文，保留准确 UTF-16 来源。图片以明确关联来源的 user 附件送入对话；较早图片附件可替换为显式提示，原始图片仍可重新检索。每批文本最多 32000 字符，范围、图像数量和总请求大小均校验。

`AgentMessage` 显式区分 user/assistant/tool。原生调用实际 ID、原始参数、可展示的简短说明和对应 tool_call_id 结果按顺序保存在内存中，`AgentModelClient.BuildMessages` 在发送前验证配对与唯一 ID。参数错误和无权调用返回有 ID 对应的工具错误，模型可按两个 schema 修正；不将历史重新封装为新用户任务。后端需要的私有续接字段只保留在同一后端的内存对话与传输中，公开序列化、日志及界面不包含这些字段。

成功轮次的原生对话会在同任务、同后端、同已提交记忆修订下继续；下一轮追加新的状态／材料消息。后端改变时用当前任务记忆建立新会话。上下文达到本地预算会明确返回错误并保留原文，不静默删除工具调用或其返回；本轮尚未实现模型摘要式的会话压缩。

每次执行冻结会话 ID、代次、记忆修订、材料、后端、场景补充和预算。未完成执行持有检查点，包括完整对话、已返回检索结果、缓存及证据覆盖。网络错误和停止后仅重试待完成模型步骤；不重放完整工具步骤，新入队材料不混入旧运行。停止后的迟到模型结果被取消与代次校验拦截。无进展自动暂停保留检查点；应用的紧急暂停、锁屏、保护失败、新任务和退出仍按既有规则清理敏感会话。

防循环按新增原文覆盖判断：已知片段可缓存复用，连续三次没有新材料给出推进／取证提示，连续六次没有新材料进入可继续的 Paused；取得新片段即重置计数。取消了全程相同动作出现三次就失败的规则。调用次数默认不限，手动调用预算允许一次提交；单次请求默认超时 300 秒，总时限默认 300 秒，各自独立生效。

`submit_result` 携带 directive 和可选 memory 修订，`CodingSession.ValidateChanges` 校验来源、容量、真实尝试 ID 和执行证据，然后原子提交。`CodingDirectivePolicy` 把平台执行边界附到可复制指令。taskComplete 必须有本轮针对最新尝试的 Verified 原始反馈；语义事实与方案正确性仍需模型及实际平台测试判断。

诊断日志保留运行／调用／工具生命周期与脱敏 HTTP 分阶段指标，另记录消息数、上下文字符数、返回片段数、缓存命中、无进展计数和检查点恢复标记。不会把正文、参数、私有续接内容、接口地址或凭据写入日志。只读回归使用本机模拟接口；显式 live evaluation 仍独立选择合成材料，不在普通测试中调用真实模型。

## 分层与信任边界（普通请求及早期基线）

```mermaid
flowchart LR
  User[用户动作 / 限时授权] --> Input[Win32 采集与剪贴板快照]
  Input --> Process[本地有序预处理]
  Process --> Prepared[冻结产物 / 模板版本 / 后端]
  Prepared --> Policy[统一发送前策略校验]
  Policy --> HTTP[单一 HTTP 客户端]
  HTTP --> Provider[显式模型端点]
  Provider --> Stream[严格响应解析与限额]
  Stream --> Generation[请求 ID 与会话代次校验]
  Generation --> Panel[受保护的文本阅读器]
  Generation --> Clipboard[完整响应 / 原子剪贴板写回]
  Pause[暂停 / 锁屏 / 保护异常] --> Revoke[代次失效 / 取消消费 / 清除引用]
  Revoke --> Generation
```

`Superb.Core` 不调用 Windows、不保存内容、不发出 UI。模型、策略、处理编排、固定路由、同步去重、请求代次与 HTTP 适配器在此层。HTTP 适配器是生产代码中唯一网络入口，模型输入仅成为用户消息的内容。

`Superb.Desktop` 使用单一 WPF Dispatcher 串行处理用户动作、授权与请求事件。所有 `Coordinator` 公共操作及事件订阅均由该事件循环调用。后台线程只负责截图与纯预处理；返回 Dispatcher 后重新检查操作代次和运行状态。后台回调排队后仍必须重新检查请求 ID，避免取消前排队的回调覆盖新状态。

请求在前端经过 Capturing → Processing → AwaitingApproval，发送后由协调器管理 PolicyCheck → Connecting → Waiting → Streaming → Completed / Failed。运行状态 Ready / Paused / Locked / ProtectionUnavailable 独立存在。取消会增加代次、使旧请求失效，并取消传输；已发送内容无法保证撤回。

处理后的快照替代原始输入引用。`PreparedRequest` 保存独立快照、不可变处理配置、无正文的可选步骤状态、后端和参数。手动重试保留这份处理结果并创建新尝试 ID。每次模型调用只有一条用户消息，不复用历史上下文。

## 需要保留的技术限制

1. API 属性校验只能发现部分异常，不能证明任意采集路径安全。没有对外标记“当前配置已测试”的按钮；只有实际取得对应构建和软件版本的证据后才能发布此结论。
2. PrintWindow 可能由目标程序绘制，硬件加速窗口可能黑帧、空白或不准确。若选定目标不可靠，应阻止发布该组合；切换到 WGC 需要另立实现和兼容性验证，不可自行回退全桌面。
3. 原生延迟剪贴板渲染、系统调用与图形驱动可能阻塞。截图已放到后台并限制未完成任务数量，但剪贴板读取仍在 STA UI 线程；严苛响应时延目标需进一步评估独立 STA/helper 进程方案。
4. UI 更新按 100 ms 合并，文档以文本段重建。大型回答的滚动位置保持和连续渲染性能尚需优化与基准；不能把此版本描述为已达成性能指标。
5. 当前托管内存实现是减少持有时间，不是可验证安全擦除。应用外的剪贴板读取、系统历史实现差异、已发送后端内容、同用户/高权限进程和物理摄像不在保护保证内。
