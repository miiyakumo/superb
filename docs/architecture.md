## 2026-10-24：AI Coding 持续任务

内置 `coding` 场景现在使用独立的 `CodingSession` / `CodingAgentRunner`；普通问答仍使用下文的单请求 `Coordinator`。场景提示词作为本次补充说明冻结，不能替代协作协议和执行权限。当前实现不连接牛客 IDE，不获取真实文件树，不执行模型生成的代码。

`CodingSession` 保存不可变的原始观察、带 `EvidenceRef` 的结构化事实，以及指令和反馈关联。`MemoryFact.Kind` 区分题目契约、问题、假设、已否定假设和结论；原始正文始终保留，模型只提交带来源的修订。观察采集时间不是文件版本。内容哈希用于原文去重，不等于确认某一次实际执行。`FeedbackObservationIds` 明确标识支持执行结果的测试反馈，共同引用同一份代码不会使两个独立失败被错误合并。

上下文只携带近期记忆摘要、最初/最近观察的目录和有界片段。`read_task_state` 分页取回完整记忆；`search_evidence` 搜索全部原文；`read_evidence` 读取准确字符范围或切换关联图片；`compare_observations` 只比较观察，不推断新旧。超大工具结果明确要求缩小范围，不丢弃原文。任务记忆在应用会话内持续存在，暂停、锁屏、保护失效或退出清理，不新增正文持久化。

每次分析冻结任务 ID、代次、记忆修订、观察集合、后端及预算。新采集的材料留在桌面待分析队列；复制指令更新转发状态，不改变技术记忆修订。反馈评估、专家分析、方案审核和最终指令全部暂存，只有当前运行完成校验和审核后才原子提交；停止、超时、错误或过期回调不能提交。失败后的“重试分析”复用冻结配置，“分析”可以显式使用当前配置重新分析保留的材料。

`ProgressAssessment` 检查实际执行、有独立反馈且可比较的失败；同策略两次失败或回退触发深入分析。模型负责语义策略归类和复杂度判断。执行器要求先评估最新指令，再发布下一条；必须深入分析时使用独立的专家请求，生成代码、正确性条件、复杂度和验证方案，随后独立审核。已保存的诊断可以覆盖相同旧失败，避免每次取证都重复分析；新事实改变依据时，旧的审核与分析不能直接复用。审核结论不是代码执行证明。

`analysis:` 是执行器保留的专家结论命名空间，普通记忆工具不能创建或覆盖。任务完成必须由本轮反馈明确验证最新指令，历史局部成功不能代替。`CodingDirectivePolicy` 在审核前将执行边界附到实际复制的提示词：修改与测试由平台完成，当前实现与依据不符时停止修改并回传，仅取证时不修改。是否缺少关键源码、题目要求是否全部满足仍由模型判断，不能把这些语义审核描述为确定性证明。

`AgentModelClient` 复用现有 HTTP handler、代理、凭据和策略，支持严格 JSON 动作或原生 `coding_action` 工具。每次请求是冻结上下文和工具结果组成的独立调用，不拼接供应商私有推理。动作参数经过类型、范围、来源和容量校验，不允许任意命令或文件工具。JSON 空修订集合可省略；验证清单只接受文本或文本数组。完整序列化请求（含工具 schema 和图片编码）及响应都有限额；累计调用、总时限、输出总量、重复工具动作和格式修复次数另外受限。

DeepSeek 思考模式使用 `tool_choice=auto`，返回仍必须是一个合法原生动作；其他已支持强制选择的配置指定 `coding_action`，不关闭思考或回退协议。该供应商限制依据 [Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/) 的 `tool_choice` 说明，并通过真实模型和本机协议测试核对。官方 DeepSeek 的 JSON 动作模式启用 `response_format=json_object`，依据其 [JSON Output 文档](https://api-docs.deepseek.com/guides/json_mode/)；通用端点不假设具有此能力。解析错误只提供固定诊断类别，不记录未校验响应正文。

桌面层的 `MainWindow.Coding.cs` 负责输入、生命周期和复制；`ReaderWindow.Coding.cs` 呈现方向、发送前操作、平台提示词和返回证据。复制直接取 `Directive.Prompt`，不从 Markdown 提取；自动写回保留剪贴板序列竞争检查。普通场景与 Coding 分别保存待发送材料及结果。

## 分层与信任边界（普通请求及早期基线）

```mermaid
flowchart LR
  User[用户动作 / 限时授权] --> Input[Win32 采集与剪贴板快照]
  Input --> Process[本地有序预处理]
  Process --> Prepared[冻结产物 / 模板版本 / 后端]
  Prepared --> Policy[统一发送前策略校验]
  Policy --> HTTP[单一 HTTP 客户端]
  HTTP --> Provider[显式模型端点]
  Provider --> Stream[严格响应解析与限额]
  Stream --> Generation[请求 ID 与会话代次校验]
  Generation --> Panel[受保护的文本阅读器]
  Generation --> Clipboard[完整响应 / 原子剪贴板写回]
  Pause[暂停 / 锁屏 / 保护异常] --> Revoke[代次失效 / 取消消费 / 清除引用]
  Revoke --> Generation
```

`Superb.Core` 不调用 Windows、不保存内容、不发出 UI。模型、策略、处理编排、固定路由、同步去重、请求代次与 HTTP 适配器在此层。HTTP 适配器是生产代码中唯一网络入口，模型输入仅成为用户消息的内容。

`Superb.Desktop` 使用单一 WPF Dispatcher 串行处理用户动作、授权与请求事件。所有 `Coordinator` 公共操作及事件订阅均由该事件循环调用。后台线程只负责截图与纯预处理；返回 Dispatcher 后重新检查操作代次和运行状态。后台回调排队后仍必须重新检查请求 ID，避免取消前排队的回调覆盖新状态。

请求在前端经过 Capturing → Processing → AwaitingApproval，发送后由协调器管理 PolicyCheck → Connecting → Waiting → Streaming → Completed / Failed。运行状态 Ready / Paused / Locked / ProtectionUnavailable 独立存在。取消会增加代次、使旧请求失效，并取消传输；已发送内容无法保证撤回。

处理后的快照替代原始输入引用。`PreparedRequest` 保存独立快照、不可变处理配置、无正文的可选步骤状态、后端和参数。手动重试保留这份处理结果并创建新尝试 ID。每次模型调用只有一条用户消息，不复用历史上下文。

## 需要保留的技术限制

1. API 属性校验只能发现部分异常，不能证明任意采集路径安全。没有对外标记“当前配置已测试”的按钮；只有实际取得对应构建和软件版本的证据后才能发布此结论。
2. PrintWindow 可能由目标程序绘制，硬件加速窗口可能黑帧、空白或不准确。若选定目标不可靠，应阻止发布该组合；切换到 WGC 需要另立实现和兼容性验证，不可自行回退全桌面。
3. 原生延迟剪贴板渲染、系统调用与图形驱动可能阻塞。截图已放到后台并限制未完成任务数量，但剪贴板读取仍在 STA UI 线程；严苛响应时延目标需进一步评估独立 STA/helper 进程方案。
4. UI 更新按 100 ms 合并，文档以文本段重建。大型回答的滚动位置保持和连续渲染性能尚需优化与基准；不能把此版本描述为已达成性能指标。
5. 当前托管内存实现是减少持有时间，不是可验证安全擦除。应用外的剪贴板读取、系统历史实现差异、已发送后端内容、同用户/高权限进程和物理摄像不在保护保证内。
